# TS6 自动识别端口与即时重连

## 已确认的目标

用户已确认：悬浮窗默认自动识别 TS 端口、成功后记住、端口变化后即时重连，保留手动模式。用户不想在 TS 和悬浮窗两边重复填写端口。

## 方案选择

- 只记住固定端口：现有软件已经保存 6200，不能解决 TS 改端口后需要同步的问题。
- 读取 TS 私有配置：依赖其内部存储结构，不作为本次实现基础。
- **采用：读取 Windows 监听表，仅使用 TS 进程拥有的本机端口，再通过 TS 协议确认连接；手动模式兜底。**

这是现有连接模块的功能扩展，不涉及前面尚未实施的应用内更新。

## 行为

1. 新增 `AutoDetectRemoteAppPort`，默认开启；旧配置仍保留 `RemoteAppPort`。
2. 启动和断开后优先使用上次成功端口，但自动模式必须确认当前监听属于 TS 进程，不能向占用旧端口的其他程序发送密钥。
3. 已记住端口不可用时，从 TS 所属的本机监听条目中寻找候选，不遍历 1–65535，也不连接其他程序端口。
4. 唯一候选可连接并认证；收到有效 auth 快照后才保存检测端口。多个无法唯一判断的候选不轮流尝试认证，提示用户用手动模式指定。
5. 没有可用连接时每 5 秒重新检测；已有健康连接时不反复查找或换端口。
6. 更换手动端口或切换模式立即重新建立连接，不需要退出应用。手动输入允许 1–65535。
7. 初次授权仍由用户在 TS 中确认；授权被拒绝后暂停自动认证重试，避免连续失败让 TS 停用接口。
8. TS 未运行、未发现远程应用监听、候选不明确、权限不足及等待授权分别提示。若 TS 接口因系统保留端口启动失败，仍需要用户在 TS 内更换端口；不承诺自动修复 TS。

## 界面与兼容

- 保留现有“连接服务器”分类，加入自动识别开关、当前连接端口和重新检测入口。
- 自动模式禁用手动编辑，显示实际检测结果；切到手动模式才允许输入端口。
- 检测成功时保存 `RemoteAppPort`，但该内部保存不能再次触发连接循环。
- 七种语言同步更新，移除“改端口需重启悬浮窗”的旧提示。
- 保留字体搜索、设置精修、名单修复、服务器选择、通知、自动启动、20 秒心跳 / 10 秒响应超时与现有配置。

## 实现约束（工程选择）

- 原生 Windows WPF/WinForms、.NET 10；不增加第三方运行依赖。
- Windows 监听表按 PID 过滤，支持 IPv4/IPv6 回环和 wildcard 监听；连接目标始终规范化为本机回环地址。
- 现有 `Ts6Service` 继续处理一个端点的协议。新增连接管理器负责检测、换端点和事件转发，旧端点的晚到事件不得覆盖新端点状态。
- 管理器创建的会话关闭其独立自动重连，由管理器统一重试；旧测试直接创建的 `Ts6Service` 保持原重连行为。
- 自动会话完成握手后、发送认证前再次核对端点归属；端口易主时丢弃会话并重新检测。

## 非目标及验证

- 不修改 TS 配置、授权开关、防火墙、Windows 保留端口或其他远程插件；不删除密钥。
- 不将此功能扩成扫描全机端口，不在健康连接期间重复探测。
- 测试覆盖端口易主、TS 重启、跨端口迁移、多个候选、授权等待或拒绝、快速切换、退出及 IPv6。
- 原目录已有本对话先前的未提交功能，执行时必须保留准确工作基线，不能从旧发布 HEAD 丢弃字体搜索或连接修复。
- 完成后更新本地说明并打包；不自动推送 GitHub 或改桌面快捷方式。
